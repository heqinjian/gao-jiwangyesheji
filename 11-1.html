CSS 长度单位

每一行色带都按它标注的单位真实渲染，右侧数字是浏览器算出的像素值。改变窗口大小或拖动下面的滑块，数字会实时刷新——这就是“绝对单位”和“相对单位”的区别。

一、绝对单位不随字体和窗口变化

绝对单位基于固定的长度换算，缩放窗口、修改字体大小都不会改变它们渲染出来的长度。

96px
1in
2.54cm
25.4mm
1pc
12pt
1Q

在 CSS 里 1in = 2.54cm = 25.4mm = 96px，所以前四行的长度完全一样；1pc = 12pt = 16px； 而 1Q = 1/40cm ≈ 0.94px，细到几乎看不见。网页开发中真正常用的只有 px。

二、字体相对单位跟着字体大小走

这一组的参照物是字体大小：em 看父元素，rem 看根元素（html）。 下面这块容器的 font-size 是 20px，根元素是 16px。

3em
3rem
12ch
4ex

同样是 3 倍：3em = 20px × 3 = 60px，3rem = 16px × 3 = 48px，长度并不相等。 ch 是数字 “0” 的宽度，配合等宽字体可以精确控制“一行放几个字符”；ex 是小写字母 x 的高度，中文场景参考价值不高。

三、视口单位跟着窗口大小走

视口单位以浏览器可视区域为参照（当前视口：--）。 拖动窗口边缘，下面的色带和数字会立刻变化；超长的色带会被卡片裁切，但右侧像素值依然准确。

10vw
25vw
50vw
10vmin
10vmax
6vh
12vh
18vh
10vmin

1vw 是视口宽度的 1%，1vh 是视口高度的 1%；vmin 取两者中较小的那个， vmax 取较大的，所以 10vmin 永远“塞得进屏幕”。移动端地址栏收缩会让 vh 跳动， 这时可以改用 dvh / svh / lvh。

四、百分比看参照物是谁

百分比没有固定长度，它永远相对于“某个父级属性”换算，所以必须先弄清楚参照物是谁。

100%
60%
30%

常见坑：width 的百分比相对父元素宽度；height 的百分比要求父元素有确定高度，否则失效； 而 padding / margin 的上下百分比也是按父元素“宽度”计算，不是高度。

五、实验台rem / em / px 对照

拖动滑块改变根元素和父元素的字体大小，观察三条色带谁在变、谁不变。

16px
20px
2rem
2em
40px

结论：px 始终不变；rem 只跟根元素走，适合做整站缩放；em 跟当前元素继承来的字体大小走， 适合组件内部按比例缩放，但嵌套多了容易“层层相乘”。

六、单位速查表

单位 参照对象 说明
px 屏幕像素 绝对单位，最常用；在高分屏上由浏览器统一缩放适配。
in / cm / mm / Q 物理长度 屏幕上仍按 1in = 96px 换算，1Q = 1/40cm。
pt / pc 印刷单位 1pt = 1/72in，1pc = 12pt = 16px。
em 当前元素 font-size 组件内部等比例缩放常用，嵌套时注意数值累乘。
rem 根元素 font-size 推荐的整体缩放方案，改 html 字体大小即可全局生效。
ch “0” 的宽度 等宽字体下按字符数控制宽度，如 60ch。
ex 小写 x 的高度 约等于 0.5em，中文环境下很少使用。
lh / rlh 行高 1lh = 当前元素一行的高度，做纵向节奏很好用。
% 父元素的同类属性 width 看父宽、height 需父高确定，padding 上下也按父宽算。
vw / vh 视口宽 / 高 1vw = 视口宽度的 1%，常用于占满一屏的区块。
vmin / vmax 视口较小 / 较大边 做自适应正方形、居中大标题时可避免溢出。
dvh / svh / lvh 移动端视口高度 动态 / 最小 / 最大高度，解决地址栏伸缩导致的跳动。
fr 网格剩余空间 只能用在 Grid 的 grid-template-* 属性里。
cqw / cqh / cqi 容器尺寸 配合 container-type 实现真正的“组件级”响应式。

书写提醒：只有数字 0 可以省略单位（margin: 0），非零值必须带单位； 混合单位运算要用 calc() 或 min() / max() / clamp()，例如 calc(100% - 2rem)； line-height 建议写无单位数字（如 1.5），它会随各自的字体大小自动换算。
